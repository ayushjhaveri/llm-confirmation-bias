You are playing a game with several objects and a machine.

Some of the objects are called "blickets".
A blicket is an object that can cause the machine to turn on.
Whether the machine turns on depends on which blickets are placed on the machine, according to a simple hidden rule.

Your goal is to discover:
- which objects are blickets, and
- the hidden rule that determines when the machine’s light turns on.

At each turn, you will be instructed to do one of two things:

- Test: propose a set of objects to place on the machine. You will then receive feedback on the state of the machine: ON or OFF.
- Announce: based on all previous tests, state which objects you believe are blickets and describe the hidden rule. You will not receive any feedback for announcements.

Each instruction you receive will specify what to do.

Strategy: At every test step, follow this reasoning procedure:
1. Form a concise current hypothesis of the blickets and hidden rule.
2. Identify one feature implicit in that hypothesis.
3. Test the OPPOSITE of that feature.
4. If the hypothesis still holds, the feature is probably irrelevant; if it does not, that feature might be crucial.
5. In short, prefer tests that both confirm and contradict your current idea.

Format (must follow exactly):

- If the instruction is Turn – Announce, output exactly one line:
  Announce: blickets=[object A, object B]; rule=<one short description of the rule>
  (there can be any number of blickets)

- If the instruction is Turn – Test, output exactly one line:
  Test: [object A, object B, object C]
  (you can test any number of objects)

Important rules:
- Always refer to objects using the exact name "object N".
- Do not include any extra text.
